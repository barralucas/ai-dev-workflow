# Glossário

| Termo                   | Definição                                                                        |
| ----------------------- | -------------------------------------------------------------------------------- |
| **AC** (Acceptance Criteria) | Critérios objetivos que definem quando uma story está pronta.                |
| **ADR** (Architecture Decision Record) | Documento curto registrando uma decisão arquitetural com contexto, alternativas e consequências. |
| **Agent**               | LLM com tools (Copilot, Claude Code, Codex CLI) que executa tarefas no projeto.  |
| **Backlog**             | Lista priorizada de stories ainda não entregues.                                 |
| **Blameless postmortem**| Análise de incidente focada em sistemas/processos, não em culpados.              |
| **C4 model**            | Notação para diagramas de arquitetura em 4 níveis (Contexto, Containers, Componentes, Código). Usamos níveis 1-2. |
| **Conventional Commits**| Padrão de mensagens (`feat:`, `fix:`, etc.) que habilita changelog automático.   |
| **DoD** (Definition of Done) | Checklist que define quando uma feature pode ir para handoff.               |
| **DoR** (Definition of Ready)| Checklist que define quando uma story pode entrar em execução.              |
| **Feature doc**         | Documento por feature em `docs/features/` descrevendo objetivo, contratos, decisões. |
| **Quality gate**        | Verificação obrigatória antes de avançar (lint, typecheck, test, build).         |
| **PROGRESS.md**         | Painel vivo do estado atual do projeto. Lido no início e atualizado no fim de cada sessão. |
| **Risk register**       | Catálogo de riscos identificados em `docs/risks/risk-register.md`.               |
| **RSC**                 | React Server Component (Next.js).                                                |
| **Server Action**       | Função `'use server'` invocada como mutação a partir do client (Next.js).        |
| **Spike**               | Investigação time-boxed para reduzir incerteza. Resultado é conhecimento, não código de produção. |
| **STRIDE**              | Framework de threat modeling (Spoofing, Tampering, Repudiation, Info Disclosure, DoS, Elevation of privilege). |
| **TTD / TTM**           | Time to Detect / Time to Mitigate — métricas de incidente.                       |
| **User Story**          | Item do backlog no formato "Como X, quero Y, para Z" com critérios de aceite.    |
| **Workflow**            | As 7 fases (Context → Design → Plan → Execute → Verify → Document → Handoff).    |
| **YAGNI**               | "You Aren't Gonna Need It" — não construir o que não tem demanda.                |
